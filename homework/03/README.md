# Homework 03 — Usability and Accessibility Audit

## Objective
Review an existing travel-related interface to identify usability and accessibility risks in the task of finding a sightseeing place, saving it, and retrieving it later.

## What I did
- Audited the Google Maps desktop flow for searching, opening place details, saving to a list, and returning to saved places.
- Examined search-result identity, place details, list selection and account dependency.
- Reviewed keyboard access, focus order, map interaction, color use, and non-text contrast against relevant usability and WCAG principles.
- Documented normal, place-result, and empty-search states, including the supplied “opirth 7224” no-results screenshot.
- Proposed improvements such as keeping place identity visible, giving explicit save confirmation, providing a text-based route, and supporting recovery.

## Audit limitation
This was a desk-based audit, not a formal usability test of Google Maps. Some loading, error, success, disabled, contrast, and focus behaviours were not verified and are explicitly marked as unverified risks.
